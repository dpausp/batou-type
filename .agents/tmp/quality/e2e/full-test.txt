## check -c basedpyright (BUG)
- classification: read-only
- invocation -> CRASH: FileNotFoundError
- exit: 1, status: CRASH
  Full traceback (abbreviated):
    File "/batou-type/src/batou_type/core.py", line 74, in check_file
      result = subprocess.run(cmd, capture_output=True, text=True, cwd=cwd)
    FileNotFoundError: [Errno 2] No such file or directory: 'basedpyright'
- root cause:
  core.py line 71: cmd = [*CHECKER_COMMANDS[c], file_path]
  CHECKER_COMMANDS[Checker.basedpyright] = ["basedpyright", "--outputjson"]
  Uses bare "basedpyright" command — relies on PATH resolution.
  When invoked from outside the venv's activate context, PATH does not
  include .venv/bin/, so the basedpyright binary is not found.
  Contrast with ty/mypy which use sys.executable -m <module> (works always).
- fix required: Use sys.executable -m basedpyright for consistency, or
  resolve the full path to the basedpyright binary from the venv.
- workaround confirmed: PATH="/batou-type/.venv/bin:$PATH" makes it work.

## Bugs Found

### BUG-1: basedpyright crashes with FileNotFoundError (CRASH, severity: HIGH)
- File: src/batou_type/core.py, line 71-74
- Cause: `CHECKER_COMMANDS[Checker.basedpyright]` uses bare `"basedpyright"` command
  instead of `sys.executable -m basedpyright`
- Impact: Any invocation of `check -c basedpyright` when venv bin is not on PATH
  will crash with an unhandled FileNotFoundError traceback
- Fix: Change CHECKER_COMMANDS entry to use `sys.executable -m basedpyright` like
  ty and mypy already do, OR resolve the binary path from the venv

## Non-Blocking Findings

1. **basedpyright output is raw JSON**: When basedpyright works (via PATH), the
   error output is JSON from --outputjson. The _filter_basedpyright_json() filters
   noise rules but doesn't convert to human-readable format. Contrast with ty's
   colored, human-friendly output. Low severity.

2. **Bare invocation exits 2**: `python -m batou_type` (no args) exits 2 because
   Typer's no_args_is_help uses exit code 2. This is a minor UX inconsistency
   with `--help` which exits 0.

3. **Stubs missing warning is passive**: When batou-stubs/batou_ext-stubs are not
   installed, the CLI shows a yellow "<not installed>" but does not warn that
   type checking will be incomplete. Users may not realize the implications.

4. **No environment preflight**: The CLI does not verify that the selected checker
   is actually available before attempting to run it. For basedpyright this causes
   a crash. For ty/mypy it would also crash if they were missing (via
   ModuleNotFoundError caught by subprocess, but the error message would be
   confusing).
